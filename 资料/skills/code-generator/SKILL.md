# 代码生成器 Skill

## 概述

根据用户描述自动生成代码。流程：理解需求 → 生成代码 → 丢给 bug-fixer 自检 → 询问后续（网页/桌面应用）。

## 触发条件

用户说出类似以下内容时立即加载此 Skill：

- "帮我写个 XX"
- "生成一个 XX 的代码"
- "写个 XX 功能"
- "帮我开发 XX"
- "generate/develop/create a..."

## 工作流程

### 第 1 步：理解需求

1. 接收用户的描述
2. **如果描述清晰明确**（指定了语言、功能、行为）→ 直接跳到第 2 步
3. **如果描述模糊或不完整**（例如"写个计算器""帮我做个工具"这种太笼统的）→ 至少问以下问题中的**必要项**：
   - 用什么语言/技术栈？（例如 Python、JavaScript、HTML/JS、C++ 等）
   - 具体要实现什么功能？（列举几个关键功能点）
   - 输入输出是什么？
   - 是否需要界面？（CLI 还是 GUI？）
   - *注意：不要一次性把所有问题都抛出去，先问最重要的 1-2 个，用户回复后再继续*

### 第 2 步：生成代码

1. 根据已明确的需求生成完整代码
2. 如果项目包含多个文件，列出文件结构
3. 代码写入用户指定的目录，或询问存放路径

### 第 3 步：丢给 bug-fixer 自检

生成完代码后，**直接加载 bug-fixer 技能**（调用 `Skill` 工具加载 `bug-fixer`），让它跑完整修复流程：

1. 告诉 bug-fixer：「刚生成的代码，帮我语法检查 + 逻辑检查一遍，有 bug 就修」
2. bug-fixer 会自行完成：定位 → 修复 → 全量检测 → 自验 → 报告结果
3. **等 bug-fixer 确认无 bug 后**，才进入下一步
4. 不要自己手动做检查——bug-fixer 的流程更完整（全量检测 + 多遍验证）
5. bug-fixer 搞不定的话（5轮上限），如实报告给用户，然后继续下一步

### 第 4 步：询问后续

自检通过后，询问用户：

> "代码生成完了，想不想把它做成一个[网站/网页应用]或者[桌面应用]？"

- 如果用户选"网站/网页应用" → 生成对应的 HTML/CSS/JS 前后端结构
- 如果用户选"桌面应用" → 使用 `html-to-windows-exe` skill 打包成 exe（或根据技术栈生成桌面版本）
- 如果用户说"不用" → 结束

## 输出规范

- 代码要带语法高亮（用代码块标记语言）
- 多个文件的要说明每个文件的用途
- 生成完成后给出运行说明
- 中文输出，口语化风格

## 注意事项

- 如果涉及敏感功能（如网络请求、文件系统操作、执行外部命令），要提示用户注意安全
- 生成代码尽量自包含，减少外部依赖
- 如果用户需要依赖管理，一并生成 requirements.txt / package.json 等
- 如果用户描述的是已有项目的功能扩展，先读已有代码再生成
