# 事件：OpenClaw 技能适配 + 整套迁移到机器 1（2026-07-17）

## 背景
大佬在机器 2（弱机）上用 OpenClaw 聊天、写 skill。之前已把 6 个自制的 WorkBuddy 格式 skill 和 openclaw.json 配置弄好，但 OpenClaw 根本不认 WorkBuddy 格式（`agent_created`/`trigger_keywords` 多行数组会解析失败，正文里调的 `Skill 工具`/`ImageGen`/`present_files`/`bug-fixer 联动` 也都是 WorkBuddy 专属，OpenClaw 没有）。今天两件事：① 把 6 个 skill 正文也改成 OpenClaw 真能跑的版本，并加一个"生成 skill 的 skill"；② 把整套 OpenClaw 转移到机器 1（强力机）。

## 过程
1. 调研 OpenClaw 自带 skill 写法（`skill-creator`/`coding-agent`），确认本地 skill = frontmatter（`name`+`description`+可选多行 `metadata`）＋**自然语言 work body**，工具调用走 bash/原生能力，没有 WorkBuddy 那套。
2. 6 个 skill 的 frontmatter 此前已改合规（`name` 小写连字符、中文目录 `图片生成器`→`image-generator`、去 WorkBuddy 字段）；本次把 **body** 改成 OpenClaw 原生等价物：
   - `Skill 工具`联动 `bug-fixer`/`code-to-website` 等 → 正文写"加载 skill `xxx`"（OpenClaw 按 description 匹配）
   - `ImageGen`/`DeferExecuteTool` 出图 → `image-generator` 加 `scripts/gen_image.py`（OpenAI 兼容/智谱 CogView，读 `IMAGE_API_KEY`/`IMAGE_API_BASE`/`IMAGE_MODEL` 环境变量）
   - `present_files` 展示 → 改为把生成文件**绝对路径**回复给用户
   - `bug-fixer` 联动自检 → `python -m py_compile` / `node --check` / `python -m http.server`+`curl` 自查，复杂可加载 `coding-agent`
3. 新增 `make-skill` 元技能：教 OpenClaw 按规范生成**格式合规且正文可运行**的 skill（含模板、work body 规则、校验脚本）。
4. 验证：`openclaw skills list` → 7 个（6 改造 + make-skill）全 `✓ ready`（source=openclaw-managed）；自定义 YAML 校验确认 frontmatter 合法、name==目录名、无 WorkBuddy 残留；`gen_image.py` 语法 OK。
5. 迁移摸底：OpenClaw 装在 WorkBuddy 托管 Node（`C:\Users\baoka\.workbuddy\binaries\node\versions\22.22.2\node_modules\openclaw`）；配置全在 `~/.openclaw`（仅 1.1MB）；本地 Ollama 模型在 `D:\ollama-models`（OLLAMA_MODELS 指向 D 盘，约 21GB），`openclaw.json` 实际只引用 `qwen3:4b`(16K 兜底) 和 `qwen2.5-coder:7b`(4K)。
6. 打包：仅复制可移植部分，剔除机器专属的 `identity/`、`state/`、`tui/`、`workspace-attestations/`；按大佬要求**不压 zip、不做桌面启动器**，直接写进 U 盘 `G:\资料\游戏成果\O啥的选文件\OpenClaw\`，并附 `迁移说明-在机器1上怎么做.md`。
