# 红米 Note 2 发布验收清单

> **每次发布必做。** 线上部署完成后，先跑自动化验收，再在红米 Note 2 真机上逐项确认。
> 自动化脚本只能覆盖可量化的部分，**真机项不能由脚本代跑**。

## 一、验收目标

| 项 | 要求 |
|---|---|
| 打开不卡顿 | 冷启动首屏 < 3 秒，不白屏、不卡在启动画面 |
| 运行流畅 | 消息列表滑动无掉帧，四个主视图切换即时 |
| 响应较快 | 点头像 / 发消息 / 同意申请，点击到界面变化无迟滞 |
| 信息同步正常 | 跨设备消息、好友申请实时到达，不丢不重 |

## 二、自动化部分（每次发布跑一遍）

```bash
node tools/release-acceptance.js
```

脚本做四类检查，结果写入 `docs/last-release-acceptance.json`：

1. **产物命名**：`轻聊.apk` / `轻聊.exe` 无版本号后缀，应用名不带版本
2. **线上资源**：网关握手、入口页 `no-store`、前端资源带内容指纹、`/api/version` 实时版本
3. **低端模拟性能**：headless Chrome 开 **CPU 4x 降速 + Regular 3G（750kbps / 100ms）**
   模拟红米 Note 2 级别的硬件，量 FCP / DCL / load / 接口 P50
4. **信息同步**：注册两个临时账号，A 发消息 → B 立刻可见；好友申请实时到达

> 模拟阈值是**防劣化底线**，不是真机达标证明。真机手感必须靠第五节的 6 项人工确认。

## 三、真机项（必须由人在红米 Note 2 上确认）

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 冷启动：划掉后台后重开 | 首屏 < 3 秒，无白屏、无卡启动画面 |
| 2 | 运行流畅：消息列表上下滑动、切「公共/房间/好友/我的」 | 无掉帧、无卡顿，切换即时 |
| 3 | 响应较快：点头像进资料页、发消息、同意好友申请 | 点击到界面变化无迟滞感 |
| 4 | 信息同步：手机发消息 → 电脑端 / 另一台设备 | 立刻收到，好友申请实时出现 |
| 5 | 深浅主题：跟随系统 / 按时间 / 手动三模式切换 | 界面即时变化、无闪白 |
| 6 | 挂后台再回前台 | 消息补齐、不掉登录、不重复渲染 |

任一项不达标 → **本次发布不算通过**，先定位再重新部署。

## 四、为什么线上更新不需要重新打包

- APK 是纯 WebView 壳，前端代码（`index.html` / `app.js` / `style.css`）全在线上
- 电脑端 `轻聊.exe` 是纯启动器，用系统 Edge/Chrome 的独立应用窗口打开同一个线上地址
- 入口页 `no-store` + 静态资源内容指纹 `?v=`：部署后重开即拉到新代码
- 版本号由 `GET /api/version` 实时下发，只在**设置 → 关于**展示

**常规更新流程：改线上代码 → 部署 → 跑本清单 → 完成。不重新构建 APK / exe。**

只有改原生层（Android Java / 权限 / 图标 / `strings.xml` 里的站点地址、或桌面启动器 C++ 源码）才需要重新构建产物。

## 五、当前版本策略（近期不改动）

- 产物文件名：**`轻聊.apk` / `轻聊.exe`**，不带版本号后缀
- 应用名称：**轻聊**，不带版本号
- 版本号**只在应用内「设置 → 关于」展示**，由线上实时下发
- 未来若调整展示位置、或应用大改版，产物可能重新加版本号 —— 但**近期不做**
- **暂不实现恢复旧版本功能**
