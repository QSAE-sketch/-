## QQ 机器人接入（关键命令）
- 装插件：openclaw plugins install @openclaw/qqbot
- 加默认通道：openclaw channels add --channel qqbot --token "AppID:Secret"
- 加多账号：openclaw channels add --channel qqbot --account bot2 --token "AppID2:Secret2"
- 多账号配置：channels.qqbot.accounts.bot2.{enabled,appId,clientSecret}，各独立 WebSocket（按 appId 隔离）。QQ 每个 bot 的 openid 独立，bot1 的 openid 不能用于 bot2。
- 连上标志（日志：C:\Users\baoka\AppData\Local\Temp\openclaw\openclaw-YYYY-MM-DD.log）：[qqbot:xxx] WebSocket connected / Gateway ready。
- 权限：channels.qqbot.allowFrom 默认 ["*"]（任何人可驱动）；收紧为你的 openid。admin 命令(/bot-me 等)要求 allowFrom 非通配 openid。

## per-channel 模型锁定（modelByChannel，已验证正确结构）
- 字段 channels.modelByChannel，schema = Record<provider, Record<targetId, model>>，支持 "*" 通配。
- 正确写法：{ "qqbot": { "*": "zhipu/glm-4.7-flash" } }  ← 该 provider 下所有账号锁死免费模型。
- 错误写法（曾踩坑）："qqbot":"zhipu/..." 扁平字符串 或 "qqbot:default":"..." → schema invalid（expected record, received string），网关启动失败。
- 注意：modelByChannel 仅当用户未显式 /model 时生效；/model directive（hasExplicitRunOverride）可绕过。新会话/重启强制回锁定模型。

## OpenClaw 无"频道级禁用 /model 指令"原生开关（重要）
- 频道 schema 的 slashCommand 字段仅 {enabled, name, sessionPrefix, ephemeral}，无 disable/deny 指令键。
- disable-model-invocation 是自定义插件命令 frontmatter（"该命令不调模型"），与系统 /model 无关。
- /model 是 framework directive，仅对 authorized sender 生效；OpenClaw 未提供 per-channel 禁用特定 slash 指令的配置。
- 若要 bot2 "铁锁"不能换模型：给 bot2 绑专用 agent + systemPrompt 写明"禁止使用 /model"（软约束，模型通常遵守）。

## 遗留坑
- openclaw.json 含明文 API Key / QQ 凭证 / gateway token，仅本机、勿外发。
- plugins.allow 在新版标 legacy（触发校验警告），应移除或改 plugins.bundledDiscovery；qqbot 靠 plugins.entries.qqbot.enabled 启用。
